# A4 形态研究室

**状态：工作台 v0.2，增加官方资料库与四视等比校准；车辆几何仍为 v0.1，不是写实车模成品。**

研究对象为 2019 年发布的 **Audi A4 B9 中期改款、欧洲标准轴距三厢版**，不是 A4L。以 Audi 官方 04/19 四视尺寸图为第一轮依据，所有车辆几何由 TypeScript / Three.js 生成。

不使用 Blender、购买/下载的车模、官网配置器的三维资产，也不使用 AI 生成图片冒充官方参考。当前仅使用尺寸图约束与人工估计的几何规则，**不是“照片自动精确重建”系统**。

## 本地运行

Node.js 22.12+ 或兼容版本；本机实际使用 Node.js 24.14.0。

```powershell
npm ci
npm run dev
```

打开终端实际输出的 `http://127.0.0.1:端口/`。不要直接打开 `index.html`。本次已后台启动的服务地址、PID 与日志位置记录在 `.runtime/preview.json`，端口是动态选择的，后续会话应重新确认。

```powershell
npm test       # 参数、几何、遮挡与导出法线回归测试
npm run build  # TypeScript 检查 + 生产构建
npm run preview
```

仅监听本机回环地址，未部署到公网。开发服务拒绝读取 `.env`、`.git`、`.runtime`、`tmp` 和 `docs` 目录。

## 已实现

- 真实三维蒙皮、轮拱缺口、独立车轮、座舱、玻璃、灯组、格栅及基础饰件。
- 自由轨道视角，正侧、正前、正后、俯视四个正交检查机位。
- 材质 / 灰色白模 / 线框；5 种估算车漆；车灯开关；前轮 ±25° 转向；自动环绕。
- 长度与轴距标尺：前侧、正侧及俯视可见；正前/正后不显示纵向标尺。
- 官方四视图和原始 PDF 查看面板；7 张官方照片的来源、发布日期与用途说明。
- **外形校准**：侧 / 前 / 后 / 顶四视锁定正交投影；模型 / 图纸 / 叠加模式；图纸不透明度、参考关键点；统一米制尺度，不提供单轴拉伸。独立校准 PNG 导出。
- **1920×1080 PNG**：仅导出三维画面，不包含网页控件。开启标尺时会包含标尺。
- **GLB 2.0**：始终输出标准材质，保留导出开始时的颜色、车灯及转向；不导出摄影棚、相机、标尺。使用米制，X 纵向（车头负方向）、Y 向上、Z 横向。
- 本地保存设置、窄屏布局、加载失败提示和资源释放。

操作：透视机位左键拖动旋转、右键平移、滚轮缩放；正交机位锁定旋转，允许平移/缩放。点击机位可复位相机。手机支持轨道手势，但桌面端更适合细节研究；窄屏暂隐藏 GLB 下载按钮。

点击顶部 **外形校准** 进入新增工作台，也可在本地服务地址后加 `/#calibration`。校准机位锁定方向及尺度，不支持拖动或缩放；切回摄影棚保留原有设置，校准的零转向不覆盖摄影棚转向。图纸未加载成功时禁用校准导出。

## 事实、估算与当前差距

官方基准为 **4762 × 1847 × 1428 mm、轴距 2820 mm**，含镜宽度 2022 mm，前/后轮距 1572 / 1555 mm。测试检查整车包围盒（包括饰件，转向归零）、车身宽度、轴心位置，而不是只显示一组正确数字。

**尺寸包围盒接近基准，不代表曲面达到了毫米级精度。** 当前模型仍有这些明显差距：

1. 车头、侧面和车尾曲率仍粗糙，局部高光不连续，部分门缝/饰条贴合不够自然。
2. 灯腔、进气口和轮毂是可识别的简化结构，不是精确复刻的选装款式。
3. 车窗是深色近似表面，没有可供近景拍摄的精细内饰；镜壳和底部遮挡也很简化。
4. 转向只是前轮旋转，不模拟 Ackermann 转向、悬架或轮胎受力。
5. 车漆参数和颜色为艺术近似，没有原厂材质测量数据。
6. 已实现官方图纸等比叠加；未实现照片相机标定、自动轮廓提取或逐点曲面误差计算，**不提供虚构的“还原率”**。图纸轮距线与主尺度有约 19 / 27 mm 的二次校核差异，不能直接认定为模型误差。
7. 未实现路径追踪、4K 成片、视频编码、开门、行驶动画或多个场景。

所以本版适合验证“公开资料 → 参数约束 → 程序化几何 → 浏览器检查/导出”的流程，**还不能当作用户最初期望的写实汽车帅照**。

## 下一轮优先级

1. 在已建资料库上补齐具体配置证据。目前 6 张外观图发布于 2022 年，仅作同代辅助；尚未核定 2019 同配置完整外观集，不混用 A4L / S line / 不同年款。
2. 利用四视校准修车顶弧线、A/C 柱、后风挡到尾厢的过渡、机盖和前后端平面曲率；固定基准不变，保留修改前后对照，不先增加更多场景。
3. 将外壳拆分为连续性可控的曲面片，精修灯腔、轮毂与门缝。
4. 补充基础内饰、真实玻璃层次和车漆反射；通过固定机位回归图检查改进是否成立。
5. 达到稳定外观质量后，再做夜景/雨地摄影棚、4K 累积渲染和视频管线。

## 验证与运行边界

- 已执行 19 项单元/几何/标定测试和生产构建，并在本地 Chrome 中检查四视叠加、桌面及 390 px 窄屏布局。
- 摄影棚与四视校准 PNG 均已解码核实分辨率；GLB 本轮回归检查头信息和导出状态，v0.1 记录另有 Three.js GLTFLoader 回读检查。
- 本次 Chrome 实际上报 **Intel UHD / ANGLE D3D11**，不是 RTX 3060；没有给出独显帧率或离线出片耗时承诺。
- 车模约 17.2 万三角面。界面显示模型几何数量，渲染器统计另包含阴影等绘制过程，二者不能混同。
- 构建保留一个主包偏大的警告（包含 Three.js）；GLTFExporter 按需加载。后续再优化首屏分包。
- 界面字体通过 Google Fonts 请求，失败时回退系统字体；车模、图纸和棚内光照本身不依赖外部资产服务器。
