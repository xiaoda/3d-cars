# BMW G20 局部曲面技术小样实施计划

> 执行方式：使用 executing-plans，逐项实现与验证。本项目已有独立研究分支；本轮不建立通用建模平台，不委派代理。

**目标：** 在用户明确确认缩小相机关的范围后，交付可多角度查看的“机盖—灯角—翼子板”局部白模，检验分区曲面路线，而非完成整车或完整车头。

**架构：** 纯函数三次 Bézier 求值及一阶导数 → 有语义的面片/边关系 → 共边一致的确定性网格 → Three.js 白模、法线和反射条纹诊断。保留相机骨架工作台，增加局部曲面对象及独立自由视角；一套控制网用于全部视角，左右镜像。

**技术栈：** 现有 TypeScript、Three.js、React、Vitest；离线 NumPy 仅用于检查照片推断。无专业建模软件、新依赖或外部三维资产。

## 设计与边界

- 采用已批准的特征线 + 分区 Bézier 路线；不采用继续增加整车统一截面，也不提前实现完整 Catmull–Clark / NURBS 内核。
- A / B 保留临时工作相机；C 仅为定性参考。原 `allowDetailedSurfaces=false` 和资料 partial 状态不冒充通过；单独记录局部技术小样授权。
- 本轮包含：半边机盖及其镜像、灯口上下/外角连接、翼子板局部上肩、真实灯口及估算内返边。其余保险杠、双肾、完整轮拱、灯内件、材质纹理、车标和整车不做。
- 主参考为已使用的 P90549627 / P90549630；P90549639 只看局部结构。不消耗留出图。照片人工取点、镜像假设、相机及深度误差均明确记录。
- 前角呈现必须是三维面片，不得用图片贴片或假黑面通过。中性白模优先；反射条纹仅检查法线连续性，不称实测光学模拟。

## 任务 1：曲面数学与共边

新增 `src/modeling/bezier.ts`、`patchGraph.ts`、`tessellation.ts` 及对应测试。

1. 先写平面、四角、解析导数对有限差分、镜像、退化输入测试；运行确认失败。
2. 实现 4×4 求值、偏导和法线；退化点明确报错，不输出 NaN。
3. 共边声明 smooth / crease；显式区分外边界和开口，不用平均法线掩盖不连续。错误边或重复配对报错。
4. 相邻面片采用相同分段数，共边位置校验并复用采样；拒绝不同密度，而不是生成 T 接点。反向边测试、确定性、绕序与非零面积测试。
5. 定向测试通过后进入实际小样，不额外扩建内核。

## 任务 2：局部控制网与技术诊断

新增 `src/vehicles/bmw-g20/patches/front-corner.json`、`frontCorner.ts`、`src/validation/bmw-g20/front-corner.test.ts`；在 `config-lock.json` 增加独立局部授权记录。

1. 记录 A/B 人工图像观察点与临时相机的镜像对照推断，不把重复拟合误差当独立验证。
2. 机盖用共享边分区控制网；有意折线、灯口边、截断边显式分类。灯口由面片围边留空并生成独立内返边，不叠加封闭蒙皮。
3. 检查所有三角形、G0、声明 smooth 的 G1、镜像、边界与开口射线；局部控制修改必须不影响灯口和其他块的边界。
4. 提供小范围机盖拱度实验参数，只有面内控制点变动；恢复可确定性返回基线。

## 任务 3：可见白模与真实浏览器验收

修改 `src/engine/bmwStudy.ts`、`src/components/BmwModelingWorkspace.tsx`、`bmw-workspace.css`；新增 `src/engine/bmwFrontCorner.ts`。

1. 增加骨架 / 局部小样选择、白模 / 法线 / 反射条纹、控制网及局部拱度对照；不改变旧相机保存数据格式。
2. 支持原图叠加与自由轨道检查。自由视角不混入照片、二维标注或相机 RMS；切回照片恢复原始研究参数。
3. 默认展示局部白模，页面明确“局部技术小样，不是完整车头”。A/B 同图、正前、高位、侧前、背面检查；C 标注仅定性参考。
4. 真实 MCP 原图文件上传、截图重开、模式往返、拱度恢复、窄屏、控制台及 A4 路由回归；仅使用已授权项目目录，后台服务不弹窗。
5. `npm test`、`npm run build`、`git diff --check`；报告实现缺陷与形态差距，再做本地提交，不推送图片。

## 完成条件 / 停止条件

工程通过不等于展示合格。交付实际白模、同图截图和数值诊断；若面片有回折/裂缝，先修局部拓扑，不扩展整车。形态只做本轮初样审阅，完整车头神态与零售展示合格仍需后续用户判断。最多两轮有目标修正的主计划不变。
