# BMW 相机复核：第一轮

用户批准继续下一阶段。本轮遵守主计划，完成一轮有边界的相机复核；相机视觉关未签收不进入曲面小样。

## 发现与选择

重新目视三张原图后，检查近侧 4 点的 PnP 多解。现有脚本只使用 SQPnP / EPnP 单一返回值，近侧仅留下焦距系数 0.85 的低位解。探索调用 AP3P 的多解返回发现，在相同骨架及相同标注下还存在前后位置不同的低位解。不能把“只有一个合格初值”误解为唯一解。

- 不选：直接把误差最小解标记为真实相机。
- 不选：为了压低误差，按照片各自变形骨架。
- 选择：固定骨架、原标注、尺度和裁剪；显式枚举多解及三档焦距先验，保留被先验拒绝的原因；把替代相机放进现有工作台直接比较。主基线不自动改写。

## 实施

1. 用合成已知相机写离线求解与坐标换算测试，四点必须包含 AP3P 多解；所有失败 / 非物理候选显式记录。
2. 生成三张开发图的候选报告，单独比较第二次人工标注带来的变化。它不是统计置信区间或独立验证。
3. 固定 A/B 原基线；C 额外保存 EXIF 先验下的低机位候选，作为歧义对照，不替代原相机文件。
4. 工作台提供选择候选、恢复及差异信息，标明“候选，不是最终校准”。保存仍沿用现有独立状态；不增加通用编辑器。
5. 在用户已授权的、仅本项目目录的新 MCP 实例中，加载原始官图，保存同图基线 / 候选叠图；目视并报告结果。
6. 跑 Python 合成测试、TypeScript 定向 / 全量测试、构建、A4 回归。提交本轮代码和报告，不推送私有素材。

## 输出与停止条件

输出候选相机、每点误差、位姿差异、真实叠图、明确的“可冻结 / 待复核”结论。若不同候选仍无法排除，保留不确定性并等待本轮审阅；不承诺通过这一轮必然恢复唯一拍摄参数，也不无限扩大搜索或补造标注。

## 本轮执行结果

数值复核、候选 UI、三图真实叠加、移动端和 A4 回归已完成；140 项 TypeScript 测试、5 项 Python 测试及构建通过。A / B 原基线保留，C 有多解与重复标注敏感性，不能自动冻结。相机关未签收，曲面小样未开始。详见 [复核报告](../research/bmw-g20/camera-review-round1.md)，其末尾列出下一轮需审阅的范围调整，而不是继续无边界调参。
