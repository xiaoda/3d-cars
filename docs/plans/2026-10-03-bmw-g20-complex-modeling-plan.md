# 宝马 G20 三厢 M Sport 复杂曲面重建开发计划

> 面向执行者：经用户确认后，使用 `executing-plans` 技能按任务执行；每个视觉关卡单独验收，不自动越过失败关卡。

**目标：** 在不使用专业建模软件、不导入现成车模的前提下，以 TypeScript 和 Three.js 重建一辆可用于零售外观展示的宝马 G20 三厢 M Sport，先证明车头多视角形态可行，再扩展整车。

**架构：** 官方资料与图像标注形成独立的证据层；相机匹配和分区控制曲面形成建模层；Three.js 承担网格生成、诊断、交互及输出。采用特征曲线驱动的分区 Bézier / B-spline 曲面，不继承 A4 的统一截面车身形状。

**技术栈：** 沿用仓库的 TypeScript、React、Vite、Three.js、Vitest；新增 TypeScript 几何与小规模拟合模块，必要时用 Web Worker。Python 仅用于资料处理等辅助任务，不作为建模软件或最终渲染依赖。

## 1 成功标准与范围

### 1.1 要交付什么

- 单一、明确配置的车型；第一版只做一种轮毂、灯组、外观套件和主参考车色。
- 桌面与移动浏览器可旋转、缩放，正常展示距离下，前脸、侧面、车尾都有稳定的车型辨识度。
- 1920 × 1080 整车展示图；车头约占画面宽度 1000 px 的近景检查图。通过后再讨论更近的微距，不用模糊的“无限缩放仍写实”当验收标准。
- 可切换中性白模、轮廓、线框、法线和反射条纹诊断视图；正式展示支持车漆、车灯及基础转向。
- 可复现的代码、控制网、资料清单、相机参数、对比图、缺陷记录和 GLB。

### 1.2 首版不做什么

不做工业级逆向测量、车身制造曲面认证、结构强度、真实光学仿真、完整底盘、机械联动、开门、完整精细内饰、雨夜场景、视频、路径追踪、车型商城或通用建模编辑器。车窗后只做正常外观视角必需的座椅、仪表台和遮挡结构。

不拿“有 BMW 标志”“三角面很多”“59 项测试通过”代替外观验收。不承诺一个没有定义的还原百分比。

### 3.3 阶段 0 的资料准入条件

目标收集约 12–20 张有用途的图，而不是追求图片数量。至少覆盖接近正前、两个不同方向的前角、侧面、后侧 / 后部及一个较高视角；关键车头形状要有至少两个有效角度交叉支持。若某视角缺失，明确是否能由其他角度补足，不用生成图片冒充证据。

每张图记录：官方图片 ID、来源 URL、原始尺寸、日期、是否摄影 / 渲染 / 草图、车型配置、可见部件、遮挡、是否动态、裁剪、可信度及用途。原始文件哈希与衍生标注分开存；只允许记录过的等比缩放、裁剪、必要的镜头校正，不拉伸图片“对齐模型”。

参数记录来源页码、单位、适用配置和置信范围。轴距可作为全局尺度约束；车高、轮距、离地高度和轮胎规格不能在配置不匹配时直接套用。

至少预留约三分之一、且不少于 3 个有效视角作为留出检查；未参与曲面拟合的图片，才可以作为独立验证。若后来用它改了模型，该图改标为开发集，并补充留出证据。

资料审计输出 `config-lock.json`、`sources.json`、`coverage.md`、`uncertainties.md`。若所选版本始终不能核定，先提交换候选或缩小目标的建议，不默默混图。

## 4 三条建模路线及选择

| 路线 | 优点 | 代价 | 决策 |
|---|---|---|---|
| 特征曲线 + 分区 Bézier / B-spline 控制曲面 + 多视图拟合 | 局部控制清楚、形状来源可追踪、适合代码和数值约束 | 需要处理共边、曲面连续性、拓扑与采样 | **主路线** |
| 手工控制笼 + Catmull–Clark 细分曲面 | 适合复杂拓扑、轮拱与车身连贯造型 | 半边结构、折痕权重、特殊顶点和拟合工具成本更高 | 主路线在车头原型中证实拓扑不合适时，再做限定部件试验 |
| 图像直接生成三维 / 摄影测量为主 | 可能快速得到粗形或参考 | 同款准确性、镜面车漆、跨图一致性和可编辑性难保证 | 不作为本次主线或依赖，不用生成结果替代真实参考 |

“复杂”指更合适的形状表达和约束，不指盲目提高面数。高质量纯代码建模仍需要反复调整控制网，它不是一键从宣传图得到原厂模型。

Three.js 官方有 `NURBSSurface`，本地安装版也包含该模块，但它主要提供曲面点求值；完整的裁剪、共边连续性、曲面网格化和拟合约束仍需项目实现。因此不声称“引入 NURBS 就自动获得 CAD 建模能力”。[Three.js NURBSSurface 文档](https://threejs.org/docs/pages/NURBSSurface.html)

## 5 主路线如何工作

### 5.1 特征曲线与分区控制网

先建立车身中线、轴线、轮心、车顶弧线、窗框、机盖两侧线、肩线、轮拱、灯外轮廓、双肾格栅边界、保险杠转折和进气口边界。曲线控制点来自尺寸与多图推断，而不是靠加几个通用截面猜整车。

把左半车身分为可管理的曲面区，再镜像主要对称部分。机盖中央、机盖侧带、翼子板冠部、灯周围过渡、保险杠中央、保险杠侧角分别有控制网；前角不再受一张大蒙皮的固定截面规律支配。油箱盖、铭牌、传感器等非对称件单独处理。

初版优先三次 Bézier 面片：位置及一阶偏导可直接求值，便于测试。规则大面需要更多局部自由度时使用 B-spline；NURBS 只在确有需要的部件使用。先证明少量面片的连接，再扩大面片数量，不一开始建设通用曲面内核。

### 5.2 共边、折线与真正的孔

- 同一连续面区域的相邻面片共用边界曲线及边界采样序列，避免 T 接点和浮点裂缝。
- 连续面要求 G0 位置相接与 G1 切平面相接；对强反射区检查曲率变化，但不承诺整车达到 G2 或工业 Class-A 标准。
- 钣金接缝、折线、硬边、开口明确分类，不错误地对所有边求光滑。
- 首选围绕灯、格栅与进气口组织面片，生成真实边界、内返边与腔体；必要时在局部 UV 域进行受控裁剪。
- A4 的凸棱柱裁孔器仅能用于其适用的简单辅助件，不当作任意 BMW 曲面的通用布尔内核。
- 灯罩是有曲率的独立表面，不是黑色平板；必须随角度改变呈现合理的深度、遮挡和反射。

### 5.3 从照片匹配相机，再调整形状

每张照片有独立的透视相机、裁剪变换和可信度。不能把透视照片贴到正交相机后照着轮廓硬拉模型。

1. 用已核定轴距、车身尺度、地面和稳定可见的轮心等建立低自由度整车骨架。
2. 通过多点投影约束估计焦距 / 视场、旋转、位置与裁剪。未知内参使用有界先验和多个初始解；单图不能宣称唯一标定。
3. 区分有固定三维对应的特征点与视角相关的轮廓点；轮廓使用投影轮廓距离，不能把每个剪影点都固定为一个车身点。
4. 先固定粗形拟合相机，再固定相机调整低自由度形状，逐步释放局部控制点。尺度、坐标原点和对称面固定，防止整体漂移。
5. 最后小范围交替优化，但不允许每张照片使用不同的车身，或通过非均匀变形图片掩盖误差。
6. 观察留出角度、侧向深度和高光，不只看参与拟合的正面。

相机模型参考 [OpenCV 相机标定与三维重建文档](https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html)。PnP 需要合适的已知三维对应，不能直接从未知车身点和无 EXIF 照片“解出精确车形”；本项目先做受约束的近似相机匹配。

### 5.4 小规模优化，而不是黑盒逆向渲染

几何目标由以下部分构成：可信特征点重投影距离、可见轮廓双向距离、官方尺寸约束、左右对称、曲面平顺性和连续边约束。不同视角分组归一化，异常点使用稳健损失；不让一个点数多的侧面压过车头。

先实现可撤销的手动控制点 / 参数编辑及报告；再对有界的少量参数做坐标搜索或有限差分最小二乘。只有诊断显示必要时才增加求解器，不先造大型可微渲染系统。不能把晴天照片中的亮斑当作真实凹凸线去拟合。

### 5.5 编辑形状与最终网格分离

源数据保存曲线、控制网、共边关系和参数，不保存一堆无法解释的最终顶点。根据曲率、弦差和展示距离生成不同精度的 `BufferGeometry`；相邻曲面先统一边界采样。用于画面评估的三角网格由同一控制曲面生成，不另外手改一个“截图专用车头”。

开发工作台只需选区、控制网显示、参数修改、锁定相机、撤销 / 恢复、JSON 导入导出和对比截图；无需通用雕刻、完整 UV 编辑器或大型 CAD 布尔系统。

当前锁定依赖是 Three.js `0.186.1`，类型包范围为 `@types/three ^0.183.0`。实施前验证新 API 的类型兼容；必要的版本调整必须单独测试，不无条件升级整个技术栈。

以下“轮次”表示有报告、对照图和明确结论的工作单元，不是工期承诺。阶段 0 完成后估算车头验证成本；车头通过后再估算整车成本。

| 阶段 | 核心工作 | 可见交付物 | 通过条件 |
|---|---|---|---|
| 0 资料与配置审计 | 精确版本、照片覆盖、规格适用性和风险 | 参考车卡片、资料拼图、缺失项表 | 关键区域有交叉证据；不混版；确定拟合与留出图 |

## 8 验收定义

### 8.1 三种检查不能混为一谈

1. **数值正确：** 稳定生成、单位明确、无 NaN、绕序正确、合法连接及导出。
2. **证据一致：** 与同版本参考图在可信视角下的轮廓、特征及深度关系一致。
3. **展示合格：** 用户认为没有明显玩具感、前脸走样或转到侧面后露馅。

三者全部需要。视觉不通过时，即使代码测试全绿，也不得写“本阶段还原完成”。

### 8.2 候选量化门槛

下面是拟定的工程验收目标，不是已经测得的精度，也不等于实车表面误差。阶段 1 根据原图分辨率和重复标注的不确定性确认，并冻结后再拟合；不能看见模型不合格就放宽。

| 指标 | 候选门槛与定义 |
|---|---|
| 整车轮廓平均双向距离 | 对有效照片，以车身投影包围盒对角线归一化，平均 ≤ 0.5%，95 分位 ≤ 1.5% |
| 车头关键点 | 以车头 ROI 宽度归一化，中位误差 ≤ 1%，95 分位 ≤ 2%；灯角 / 双肾等关键点逐项报告 |
| 留出视图 | 与开发集分别报告，不用全图平均掩盖某个角度；不可见、模糊或争议区域提前标记 |
| 共边位置 | 对声明连续的边，数值差 ≤ 1e-5 m；只是算法拼接误差，不是实车精度 |
| 共边切平面 | 声明光滑的边，采样法线夹角目标 ≤ 1°；同时检查条纹，不允许仅平均法线 |
| 镜像 | 主对称曲面数值一致；明确列出的非对称件除外 |
| 拓扑 | 无意外孔洞、反面、退化面、明显自交、闪烁；面板缝和开口允许且需声明 |
| 导出 | GLB 回读后尺度、可见件、材质、法线和姿态一致 |

原图中的胎影不当轮廓；动态轮胎不当静态圆；曲面高光不当固定特征线。相机误差与几何误差分开记录。若标注噪声已超过候选门槛，先改评估条件，不用伪精度。

### 8.3 视觉验收包

每轮固定输出：正前、左右前角、侧面、后侧、正后、较高前角；另有车头局部。白模、反射条纹、深浅两种中性车漆使用冻结的灯光、曝光与相机；标明真实照片相机与自由展示相机的区别。

车头必看：双肾宽高与倾角、中央鼻梁、灯的外角与折向、机盖前缘高度、翼子板隆起、轮拱唇边、保险杠突出量、进气口深浅与风挡下沿接合。关闭灯光和标志后也应保留明显的 G20 造型特征，但不以“看出是 BMW”作为唯一通过条件。

对照图固定为原图 / 渲染 / 叠加 / 标注差异，不只交一张最好看的斜前方图片。正式报告中同时展示残留的最大问题。

## 9 停止和改线规则

1. **资料关未通过：** 配置不一致，或关键车头深度在有效视角中没有约束。先补公开证据或提出更换 G20 年款；无法解决就暂停该候选，不进入细节建模。
2. **相机关未通过：** 一套合理骨架无法同时解释多张图。先检查裁剪、镜头、动态姿态、版本混用和标注，不立刻把车身扭歪。
3. **曲面关未通过：** 适当调参仍出现回折、连接问题或控制耦合。重做局部拓扑；仅在小样中比较细分曲面路线，不全车换系统。
4. **车头验证：** 首次白模之后最多安排两轮有明确目标的修正。每轮针对最大的三个视觉缺陷，提交相同机位的前后对照、开发 / 留出指标以及变化原因。
5. **两轮后仍明显不像或无实质进步：** 停止新增部件，报告是资料不足、相机不确定、表达方式不足，还是当前实现 / 调形能力不足。由用户决定补资料、改路线、缩小展示范围或终止；不继续以“下一轮细节会解决”推进。
6. **数值过关但用户不认可：** 仍视为视觉关未通过。若只适合有限机位，交付标签必须写明，不把有限视角模型包装成自由旋转零售成品。

## 10 性能与部署边界

先用现有电脑和浏览器实际 GPU 测量，不把机器有 RTX 3060 等同于网页使用独显；A4 最近的实际浏览器记录为 Intel UHD。

初始工程预算建议：交互 LOD 约 15–30 万三角面；高质量静态 LOD 可试 40–80 万；主色贴图优先 2K；整车资源体积目标 20 MB 以内；交互目标为受控 DPR 下约 30 fps。全部是待基准测试调整的预算，不是性能承诺；不得为了面数预算提前牺牲尚未验收的车头形状。

细分 / 求解只在数据改变时运行，不每帧重建。先测主线程成本，再把纯几何计算放到 Worker，以可转移数组返回；场景对象、材质和渲染仍在主线程。装饰件合批 / 实例化前保留语义映射，测量实际渲染调用，不以 Mesh 数等同 draw calls。

最终控制网是可编辑源，GLB 是可再生交付资产；导出用官方 GLTFExporter，并通过 GLTFLoader 回读。必要的异步图像 / Blob 处理须在实际浏览器验证，不假设浏览器导出器可不经适配直接运行于 Node。[GLTFExporter 文档](https://threejs.org/docs/pages/GLTFExporter.html)

商业发布前单独核对参考图片、标识、环境贴图和输出资产的使用条件。本地参考默认放在不被 Vite 服务的忽略目录；只公开自建且符合使用条件的资源。是否允许零售上线是独立检查，技术上能展示不代表素材已获许可。

## 11 架构决策记录

以下为已批准计划的 ADR 摘要；阶段 0 未以此绕过后续视觉关卡。

| 决策 | 理由 | 代价与备选 |
|---|---|---|
| ADR-01 使用特征曲线驱动的分区曲面 | 局部可控、便于追踪照片约束，解决统一截面表达不足 | 自行处理拓扑 / 连续边；必要时只对困难部件试控制笼细分 |
| ADR-02 先相机与低自由度骨架，再细化曲面 | 降低用错误形状补偿错误透视的风险 | 多解无法完全消除，必须保留不确定性与留出图 |
| ADR-03 车头验证先于全车精饰 | 最早验证用户最在意、也最容易失败的部分 | 会先出现局部精细、后部占位的实验版本，必须标明 |
| ADR-04 控制曲面与渲染网格分离 | 可以改变网格精度而不改造型定义 | 构建流程增加一层，需要确定性与缓存 |
| ADR-05 保留 A4，BMW 先独立入口 | 可回退，避免重构平台吞掉建模时间 | 少量短期重复，造型过关后再抽最小接口 |
| ADR-06 人工视觉签收与自动测试并列 | 测试无法证明“足够像实车” | 需要每个关卡由用户审阅，不可全自动放行 |

5. 运行 `npm test -- src/validation/bmw-g20/front-proof.test.ts`，再全量测试 / 构建。用户未签收就不开始任务 10。

### 任务 10 扩展全车一级曲面

### 任务 11 识别部件与可见内饰

## 14 批准后第一批工作

只执行任务 0–1：建立隔离基线、完整审计候选参考车、确定同一套配置、列出覆盖缺口并交付资料卡片。随后才进入相机与曲面小样。主路线为本会话顺序执行、每关复核；没有默认安排并行代理。

这份计划提高的是试验的可控性与失败可定位性，不保证公开图片最终一定足以满足预期。是否值得完成整车，由阶段 3 的实际车头结果决定。
