# A4 官方参考资料与四视校准工具实施计划

> 执行：采用 writing-plans / executing-plans 流程，当前会话按任务实施和检查。用户已确认开始；不委派代理。项目没有 Git 元数据，不创建工作树或伪造提交。

**Goal / 目标：** 固定可追溯的官方参考资料，并用真实尺度下的图纸/模型叠加暴露 v0.1 的外形差异。

**Architecture / 架构：** 保留原有摄影棚；新增独立校准工作台，复用纯代码车模，在锁定正交相机下显示官方原始图纸与模型。图纸像素坐标到米制坐标采用有记录的等比变换。参考数据、标注、渲染与 React 控件分离。

**Tech Stack / 技术栈：** React、TypeScript、Three.js、Vitest、现有 Vite 本地服务。只使用官方公开资料，不使用第三方车模、Blender 或生成式参考图片。

## 边界

- 本轮先交付资料与校准工具，不将其冒充已完成精细车模。
- 图纸是官方尺寸基准；局部图像坐标是人工取点，非原厂 CAD。
- 照片必须注明来源、发布日期/素材编号、可确认与无法确认的配置。
- 不将透视照片当作正交图；不将 S line / Avant / S4 细节混入基础尺寸图。
- 固定等比尺度、方向与基准，不提供任意非均匀拉伸或未定义的还原率。
- 校准导出为对比图，不替代摄影棚成片；正常 PNG / GLB 导出保留。

## 任务 1：资料核对与冻结

1. 查阅官方 2019 发布页面与图库，查验单张照片的日期、身份和可见配置。
2. 保存少量用于本地研究的官方照片、来源元数据及 SHA-256，不下载整个媒体库。
3. 建立 `src/data/references.ts` 与 `docs/research/2026-10-02-a4-reference-audit.md`，明确主基准、辅助和排除资料；资料缺口如实保留。

## 任务 2：有尺度的坐标映射（TDD）

文件：`src/data/calibration.ts`、`src/data/calibration.test.ts`。

1. 先写失败测试：侧视轴距、前视车宽、后视含镜宽、俯视车长、等比映射和正反方向；前后轮距作为二次校核，保留图纸残差而不强行拟合。
2. 运行 `npm test`，确认因缺少实现失败。
3. 实现原图裁切窗口、像素锚点、米制转换、关键点与合法设置校验。
4. 测试通过后记录取点方法与图纸自身误差，不承诺毫米级精度。

## 任务 3：校准引擎和界面

文件：`src/engine/calibration.ts`、`src/components/CalibrationWorkspace.tsx`、`src/App.tsx`、`src/style.css`。

1. 新增“摄影棚 / 外形校准”切换，不重写现有工作台风格。
2. 提供正侧、正前、正后、俯视，模型 / 图纸 / 叠加模式、图纸透明度和关键点显示。
3. 相机锁定方向与等比尺度，画面自适应窗口；支持校准 PNG 导出和加载失败反馈。
4. 提供参考资料卡片/来源链接以及已知差异清单，不给模糊参考假装已核定具体动力配置。
5. 校准视图固定零转向并单独持有资源，不影响摄影棚设置，切换时正确释放。

## 任务 4：验证与交付

1. 单元测试、TypeScript 与生产构建通过。
2. 确认已有后台服务归属并复用；Chrome DevTools 先 list_pages 再新建本任务独立页面。
3. 查看四个方向的真实截图，检查方向、轮位、基准线和透明度切换。
4. 验证导出图片分辨率、切回摄影棚、移动端和控制台；图纸失败不得显示伪造内容。
5. 保存 QA、更新 README；在结果中分别报告“工具完成”与“外形仍待精修”。
