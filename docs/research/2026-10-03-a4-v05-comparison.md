# A4 v0.5：座舱边界、门框和机盖过渡

基线：`124bfa5`（v0.4）。本轮是局部几何校正，不是完整车体重建，也未达到写实汽车成片质量。

## 观察条件

- 前侧 `(-6.5, 2.6, 6)`、后侧 `(6.5, 2.35, -6)`，目标 `(0, 0.7, 0)`。
- 石墨灰车漆 / 原白模材质，关闭车灯、零转向；摄影棚灯光、环境、曝光和材质参数不变。
- 四视等比叠加沿用原标定；观察模式 80% 图纸，也检查纯模型，不能靠叠加图线掩盖模型问题。
- 本轮没有进行照片相机标定，官方照片只提供形态组织参考，不给出照片像素误差或还原率。

## 1. 座舱：先改边界，不换玻璃材质掩盖问题

原前后风挡分别以两个固定纵坐标裁切，横向边界偏直；本轮将前后缘改为随横向位置变化的弧线，并加入共用边界的密封条。侧框增加轻微横向曲率，车顶横向拱度向边缘集中；原纵向车顶控制点未改。

B 柱由固定 x 的直切改为斜切；后门窗与后三角窗拆分，侧窗整体二维轮廓保留。车顶、玻璃和左右侧框使用朝外的法线，玻璃和柱板的绕序同步校正。

观察：风挡边界不再是原来的直切四边形，后三角窗和斜置窗柱可以区分。但风挡下沿仍有较宽的车身色过渡区，A/C 柱厚度和曲率仍显概括；玻璃依然是深色近似表面，没有透射层次和内部结构。不能称为真实座舱重建完成。

## 2. 门框：用图纸路径取代随手折线

从冻结 PDF 人工确认路径 951、950（第 2 项起）和 1011，采样前后门下部边界；原图、等比标定不改。B 柱侧的分缝、前门前沿、后门向轮拱前方收束和底边不再由几段任意折线定义。前门把手小幅前移以避开新的门框边界。

这些路径仍是附着在连续蒙皮上的细管几何，**不是在车身上切开真正的门板缝隙**，不支持开门。低分辨率下细线仍可能出现轻微锯齿。

## 3. 机盖：修复可定位的斜率跳变

原前角抬升使用 `max(0, -x-1.90)`，在入口处有一阶斜率跳变。新回归先在旧实现上失败，再改成端点平缓收束的三次权重，降低抬升幅度。新 `bodyTopPoint()` 按实际截面半宽比例定位机盖和尾厢侧线，代替选择任意截面网格索引。

观察：原入口折痕减轻，机盖线条更明确；但机盖前缘仍偏圆、外角仍有局部高光收紧。解决一个数值折痕不等于获得正确实车曲率，更不是 A 级曲面认证。

## 样张与可复现性

v0.4 基线只读保留：[前侧深色漆](v04/after-front-paint.png)、[后侧白模](v04/after-rear-clay.png)、[侧视模型](v04/after-side-model.png)、[俯视叠加](v04/after-top.png)。

本轮通过 Chrome DevTools 的默认截图及应用 `exportFrame()` 返回的实际 PNG 查看新画面（不是 AI 图片）。工具明确拒绝将截图/脚本结果写入本项目指定路径，故没有绕过限制，也没有把新图伪写成已归档。新 PNG 在浏览器内存解码检查为 1920×1080，导出结果记录在 [export-check.json](v05/export-check.json)。

本地摄影棚可复现固定机位；开发者控制台的内部检查接口如下。它只更新引擎，不同步 React 控件，检查结束刷新页面即可回到界面设置。

```js
const s = window.__A4_STUDY__;
s.update({...s.inspect().settings, mode:'paint', paint:'graphite', lights:false,
  steering:0, rotate:false, dimensions:false});
s.setInspectionPose([-6.5, 2.6, 6], [0, .7, 0]);
// 后侧改为 [6.5, 2.35, -6]；白模将 mode 改为 'clay'。
```
