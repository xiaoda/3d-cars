# BMW G20 阶段 1：相机与骨架工作台

日期：2026-10-03。分支 `feat/bmw-g20-surface-study`，基线 `31dcbde`。

**结论：本批工程实现完成；相机与原图的完整视觉关未完成，不进入精细曲面开发。**

## 1 已实现

1. `src/modeling/types.ts`：米制 / 弧度的证据约束、官方来源检查、显式未知值、4×4 三次面片控制点契约。这里只定义和验证控制网，尚未实现曲面求值。
2. `projection.ts`：Three.js 透视相机、位姿、原像素/归一化坐标转换、裁剪窗口、画面内判定和显式可见性。骨架无遮挡面，**未实现自动遮挡识别**。
3. 同一份 `skeleton.json`：轴距、玻璃角点、轮毂外端面中心、轮圈占位和车身结构线。主对称部分左右镜像，X 向前为负、Y 向上、Z 向左，原点在两轴中点的地面投影。
4. `landmarks.json`：P90549627 / 30 / 35 的 16 个固定对应候选、人工重复选点及视角相关的粗轮廓。所有三维对应均为近似骨架假设，不是测量数据。
5. `cameras.json` 与离线生成脚本：冻结同一骨架，只生成三套相机初值，不按照片改变车身、不修改或拉伸原图，不读留出照片参与拟合。
6. 独立 `/#bmw` 工作台：三机位、原图选择和哈希核对、骨架/原图/叠加、透明度、关键点与残差线、粗轮廓显示、相机锁定、位置/视场角编辑、保存/恢复、JSON 导入导出。

工作台按需加载，没有移植 A4 车身，也没有重构车型平台。没有新增 npm 依赖。Python/OpenCV 仅用于离线初值生成，网页运行只需要原 Three.js 技术栈。

## 2 尺度、相机与证据边界

- 2.851 m 轴距、1.445 m 高度是从技术表借用的**研究尺度假设**，全部标成 `approximation`；阶段 0 的尺寸 `pending` 保留。没有宣称拍摄车已确认 xDrive 或该悬架高度。
- 轮毂标注落在可见端盖中心，不是轮距定义中的轮胎中面。骨架端盖横向位置 ±0.866 m 是近似值；轮胎半径 0.3313 m 由前胎标称尺寸推算，不含载荷变形，后胎仍未知。
- 相机以 EXIF 和“36 mm 对应原图宽”假设初始化，尝试 0.85 / 1.00 / 1.15 三个焦距先验，各用 SQPnP / EPnP 初值再 LM 细化。没有开放任意图像变形去消除误差。
- OpenCV 的位姿换算到 Three.js 相机的负 Z 观察约定，并以两个实现逐点核对。使用原图连续像素坐标、左上原点。[Three.js 相机](https://threejs.org/docs/pages/Camera.html)、[PerspectiveCamera](https://threejs.org/docs/pages/PerspectiveCamera.html)
- PnP 需要三维与二维对应；这里三维点来自近似骨架，所以输出只是**在这些假设下的匹配相机**，不能声称恢复真实拍摄参数。[OpenCV PnP 说明](https://docs.opencv.org/4.13.0/d5/d1f/calib3d_solvePnP.html)
